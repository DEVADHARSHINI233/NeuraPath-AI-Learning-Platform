# NeuraPath — AI-Powered Learning Recommendation Platform

A full-stack final-year CSE project: an AI-driven learning platform that recommends
courses, analyzes resumes, guides career paths, runs adaptive quizzes, and answers
questions through a retrieval-based chatbot.

> **Scope note:** The original brief requested an enormous list of subsystems (mock-interview
> AI scoring, full LLM+RAG chatbot, live compiler integration, 1000+ synthetic students, etc.).
> This build focuses on a smaller set of features implemented **fully and correctly** rather
> than a long list implemented as non-functional stubs. See "Roadmap / what's not included"
> at the bottom for what would need to be added for 100% coverage of the original brief, and
> how each piece would plug into this same architecture.

---

## 1. What's included

| Module | Description |
|---|---|
| **Auth** | Register/login with JWT, role-based access (student / faculty / admin), password hashing |
| **AI Recommendation Engine** | Content-based filtering using **TF-IDF + cosine similarity** between a learner's interests/skills/goal and every course's tag vector |
| **Resume Analyzer** | PDF/text upload → skill extraction, missing-skill gap analysis vs. target role, heuristic **ATS score**, improvement suggestions |
| **Career Guidance** | 7 structured roadmaps (Full Stack, Data Science, ML, Cloud, Cyber Security, DevOps, Android) with skills, salary bands, hiring companies |
| **Adaptive Quiz System** | MCQ quizzes across 7 categories, auto-graded, feedback based on score, results feed the dashboard's "weak topics" panel |
| **AI Chatbot** | Retrieval-based Q&A: TF-IDF similarity search over a 20-entry knowledge base (DSA, ML concepts, placements, resumes, career advice) |
| **Dashboard & Analytics** | Student dashboard (quiz trend chart, weak topics, top picks) and Admin dashboard (enrollment stats, category breakdown, top courses) |
| **Course Catalog** | Search/filter by category & difficulty, enroll, course detail pages |
| **Profile** | Editable interests, skills, skill level, career goal — these directly drive the recommendation engine |

**Tech stack actually used:** React 18 + Vite + Tailwind CSS (frontend), Flask + REST API (backend),
SQLite for zero-config local dev with a MySQL-compatible schema script for production, scikit-learn
(TF-IDF/cosine similarity), PyJWT, Docker + docker-compose.

## 3. Quick start — Option A: Docker (recommended)

Requires Docker + Docker Compose installed.

```bash
cd project
docker-compose up --build
```

- Frontend: http://localhost:8080
- Backend API: http://localhost:5000/api/health

The backend image seeds its own demo database automatically on build.

## 4. Quick start — Option B: run locally without Docker

### Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python seed_data.py             # creates & seeds database.db (run once, or any time to reset)
python app.py                   # starts on http://localhost:5000
```

### Frontend (separate terminal)

```bash
cd frontend
npm install
npm run dev                     # starts on http://localhost:5173, proxies /api to :5000
```

Open **http://localhost:5173**.

## 6. How the recommendation engine works

1. Each course is represented as a document: `title + category + tags + difficulty`.
2. The learner's profile is represented as a document: `interests + skills + career_goal + skill_level`.
3. `TfidfVectorizer` (scikit-learn) fits a TF-IDF matrix across all course documents plus the
   learner's document.
4. `cosine_similarity` scores the learner's vector against every course vector.
5. Courses are ranked by similarity score (shown in the UI as a **match %**).
6. Cold start (no interests/skills yet) falls back to highest-rated courses.

This is a real, working content-based filtering pipeline — not a mock. You can inspect it in
`backend/app.py` under `build_recommendations()`.

Quiz results also feed the dashboard's "weak topics" panel (lowest average score per category),
giving a simple adaptive-learning signal without needing a separate ML model.

## 7. Database

- **Local/demo:** SQLite (`backend/database.db`), created and seeded by `seed_data.py`. Zero
  configuration required.
- **Production reference design:** `backend/schema.sql` — a normalized MySQL 8 schema with
  foreign keys, indexes, and a full-text search index on courses, matching the same tables
  used by the SQLite version (`users`, `courses`, `enrollments`, `quiz_questions`,
  `quiz_attempts`, `resume_analyses`, `chat_logs`, `certificates`).

To run against real MySQL in production, swap the `sqlite3` calls in `app.py` for a
`mysql-connector-python` or `SQLAlchemy` engine pointed at a database created from `schema.sql`
— the query shapes are already parameterized and portable.

## 9. Security notes

- Passwords hashed with Werkzeug's `generate_password_hash` (PBKDF2).
- JWT-based auth with expiry; role checks enforced server-side via a decorator.
- All SQL uses parameterized queries (no string-interpolated SQL) — prevents SQL injection.
- CORS enabled for the frontend origin; tighten `CORS(app)` to a specific origin list in production.
- File uploads for resumes are read in-memory and not executed; validate file size/type further
  before production use.
- For production: move `SECRET_KEY` to an environment variable/secrets manager (already
  externalized via `os.environ` — just set it), add rate limiting (e.g. Flask-Limiter), and
  serve behind HTTPS.

## 10. Roadmap / what's not included (from the original brief)

To keep every included feature genuinely functional, the following from the original spec were
**not** built, but the architecture supports adding them incrementally:

- **True LLM + RAG chatbot** — currently a TF-IDF retrieval bot over a static KB. Swapping in an
  LLM API (e.g. calling an LLM provider from `chatbot_reply()` with the KB entries as retrieved
  context) is a natural extension of the same function.
- **Mock interview AI scoring** (confidence/communication analysis) — needs speech/video input
  processing, out of scope for a REST+SQLite demo.
- **Coding practice + compiler integration** — needs a sandboxed code execution service (e.g.
  Judge0) wired to a new `/api/coding` module.
- **Certificate generation with QR codes**, **email notifications**, **Google login**, **forum,
  wishlist, bookmarks, badges/leaderboard UI** — straightforward CRUD additions on the existing
  schema pattern, trimmed here to keep the delivered scope fully working end-to-end.
- **1000+ synthetic students / 10,000+ learning records** — `seed_data.py` currently generates a
  smaller, representative dataset (40 students, 60 courses, ~45 quiz questions) so the demo
  stays fast; the generators are parameterized (`gen_students(n)`, `gen_courses(n)`) — raise `n`
  to scale up.
